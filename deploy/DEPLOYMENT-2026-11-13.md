# Развёртывание двух VPS — 13 ноября 2026

## Рабочая схема

```text
Клиент → 83.141.70.144:51820/UDP → 201.51.10.213:42645/UDP → Интернет
```

- Российский вход: `pepa-relay.service`, nftables DNAT/SNAT, автозапуск включён.
- Голландский выход: существующий контейнер `amnezia-awg2`, интерфейс `awg0`.
- Существующий бот: `/root/amnezia-bot`, `amnezia-bot.service` на голландском VPS.
- Новые профили: `ENDPOINT_HOST=83.141.70.144`, `ENDPOINT_PORT=51820`.
- Токен, администраторы, остальные параметры `.env`, ключи и существующий клиент сохранены.
- Inventory: `deploy/two-vps.json` (локальный файл, исключён из git).

## Проверки

- Семь автоматических тестов и проверка round-trip `vpn://` прошли.
- Linux-тест `test/relay-netns.sh` прошёл: DNAT/SNAT, обратный путь, изоляция,
  повторная загрузка правил и отказ выхода.
- `node deploy/two-vps.js --check` завершился успешно.
- Временный AmneziaWG-клиент в отдельном Docker-контейнере на голландском VPS
  подключился к российскому endpoint. На сервере подтверждён свежий handshake
  с адреса российского relay. HTTPS-запрос через VPN к Cloudflare показал
  внешний IP `201.51.10.213`; маршрут запроса проходил через тестовый VPN-интерфейс.
- Тестовый peer добавлялся только в runtime, затем удалён вместе с контейнером.
  Остался один исходный peer. Контрольные суммы `awg0.conf` и `clientsTable`
  совпали с исходными; остальные поля `.env` также проверены на неизменность.
- Relay активен и включён в автозапуск; бот активен, `NRestarts=0` после обновления.

Проверка выполнена с серверного тестового клиента. Подключение с пользовательского
устройства, его DNS/IPv6/kill switch и работа после полной перезагрузки VPS отдельно
не проверялись.

## Использование и обслуживание

Новый профиль можно получить обычной командой `/add` у существующего бота.
В ранее выданном `.conf` для этого голландского AWG-сервера нужно заменить
`Endpoint` на `83.141.70.144:51820`, сохранив остальные поля.
Профили от другого VPN-сервера могут иметь другие ключи и этой заменой не переносятся.

Проверка из корня репозитория:

```powershell
node deploy/two-vps.js --check
```

Повторное применение:

```powershell
node deploy/two-vps.js --apply
```

Откат к прямому подключению:

```powershell
node deploy/two-vps.js --rollback
```

Перед развёртыванием устаревший прямой endpoint `201.34.152.121` исправлен
на `201.51.10.213:42645`. Поэтому штатный rollback возвращает бот на **новый
голландский адрес**, затем отключает relay. Уже импортированные клиентские
профили автоматически не меняются.

Резервная копия исходного кода и `.env` находится только на голландском сервере:
`/root/pepa-deploy-20261113/bot-before.tar.gz` (каталог закрыт для других пользователей).
Архив содержит исходный `.env` со старым адресом; полное восстановление этого архива
не равнозначно штатному rollback.

Состояние отката endpoint: `/root/amnezia-bot/.two-vps-state.json`.
Конфигурация relay: `/etc/pepa-relay/` на российском VPS.
Серверный тест: `/root/pepa-deploy-20261113/relay-e2e.py` на голландском VPS.
